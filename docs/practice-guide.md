# 四个可以手算的面试练习

算法题适合先预测几个输入的输出，再提交代码。工程模块还要解释数据形状、跨步保留的状态，以及哪些测试能区分两种实现。下面的例子可以直接带到题库中练习。

## 滑动窗口的左端什么时候移动

**对应练习：最长单一出现片段。** 给定一串 token，求元素互异的最长连续片段。试着只记每种 token 最近一次出现的下标，想清楚读入一个新 token 时，前面的哪些信息足以确定新的左端。

**术语**

- 循环不变量是每次迭代在同一位置都成立的条件。本题在处理完下标 `right` 后，`[left, right]` 是以此处结尾的最长互异片段。
- `last[x]` 是 token `x` 最近一次出现的下标。处理当前 token 时，先按旧值计算左端，再把当前下标写入字典。

依次读入 `["a", "b", "b", "a", "c"]`。若当前 token 的旧位置在窗口内，就把左端移到旧位置后一格。若旧位置落在窗口左边，沿用原来的左端。这个规则可写成 `left = max(left, last.get(x, -1) + 1)`。

| 当前下标 | token | 新左端 | 当前窗口 | 当前最长长度 |
| --- | --- | --- | --- | --- |
| 0 | a | 0 | a | 1 |
| 1 | b | 0 | a, b | 2 |
| 2 | b | 2 | b | 2 |
| 3 | a | 2 | b, a | 2 |
| 4 | c | 2 | b, a, c | 3 |

第 3 个下标最能暴露错误。直接采用字典中旧位置加一会让左端倒退到 1，把两个 b 都放进窗口。面试时可以这样说明正确性：“After each step, the window is the longest suffix ending here that contains distinct tokens.” 每个元素只作为右端处理一次，平均时间复杂度为 O(n)。

## 从 MHA 写到 GQA 时，哪些维度发生变化

**对应练习：缩放点积注意力、因果自注意力、多头自注意力层、分组查询注意力层。** 先写出一行注意力的加权和，再把这一步扩展到多个头。

**术语**

- Q、K、V 分别表示 query、key、value。每个 query 与各 key 计算相似度，得到分配给各 value 的权重。
- B、T、D 分别表示批大小、序列长度、输入隐藏维度。Hq 和 Hkv 分别是 query 头数和 key/value 头数。每头维度 d = D / Hq。
- MHA 为每个 query 头配一组独立的 K、V。GQA 让连续的一组 query 头共享一组 K、V。每组包含 Hq / Hkv 个 query 头。

取 B=2、T=3、D=8、Hq=4，则 d=2。两种结构都先从输入 `[2,3,8]` 投影出 Q，再拆头并交换序列轴与头轴。

| 张量 | MHA，Hkv=4 | GQA，Hkv=2 |
| --- | --- | --- |
| Q 拆头并转置后 | [2,4,3,2] | [2,4,3,2] |
| K 或 V 拆头并转置后 | [2,4,3,2] | [2,2,3,2] |
| 每个 query 头的分数矩阵合在一起 | [2,4,3,3] | [2,4,3,3] |
| 合并 query 头后 | [2,3,8] | [2,3,8] |

GQA 中 query 头 0、1 用第 0 个 KV 头，query 头 2、3 用第 1 个 KV 头。用 `repeat_interleave(2, dim=1)` 可得到这种对应。每头计算 `Q @ K.transpose(-2, -1) / sqrt(d)`，沿最后一维执行 softmax，再乘 V，最后合并各头并做输出投影。解码时可以只缓存原有的两个 KV 头。

**手算验证。** 取一个序列、两个位置，让 Q 全为 0，让第 0 个 KV 头的两个 value 分别为 [2,0]、[6,0]，第 1 个 KV 头则为 [0,3]、[0,9]。双向注意力的两个 key 权重各为 1/2。合并前四个头的输出依次为 [4,0]、[4,0]、[0,6]、[0,6]。加上因果遮罩后，第一个位置仅可访问自己，前两个头的该位置输出都变成 [2,0]。这个例子能同时检查分组、归一化轴和遮罩方向。[GQA 论文](https://aclanthology.org/2023.emnlp-main.298/)

## 手算 AdamW 的第一次参数更新

**对应练习：带状态的 AdamW 优化器。** 从一个标量参数开始，分别记下权重衰减和梯度更新各自带来的数值变化。

**术语**

- g 是本步梯度，m 是梯度的指数移动平均，v 是梯度平方的指数移动平均。t 是该参数实际执行更新的步数。
- η 是学习率，λ 是权重衰减系数，β₁ 与 β₂ 分别控制 m 和 v 的历史权重，ε 加在校正后的平方根外侧。
- 偏差校正把第 t 步的 m 与 v 分别除以 `1 − β₁^t` 和 `1 − β₂^t`，得到 m̂ 和 v̂。

令初始权重 w=2、m=v=0，取 g=3、η=0.1、λ=0.2、β₁=0.9、β₂=0.99、ε=10⁻⁸。第一次更新如下。

1. 解耦权重衰减得到 `w_decay = 2 × (1 − 0.1 × 0.2) = 1.96`。
2. 更新两个状态，得到 `m = 0.1 × 3 = 0.3`、`v = 0.01 × 9 = 0.09`。
3. t=1 时，偏差校正得到 m̂=3、v̂=9。权重更新后为 `1.96 − 0.1 × 3 / (3 + ε) ≈ 1.86`。

**定位错误。** 从同一初始状态单独运行三组输入。g=3 时输出约 1.86，g=0 时输出 1.96，梯度为 `None` 时参数和步数都保持初值。接着从 g=3 的状态追加一个零梯度步骤，历史动量仍参与更新。把这两步的参数依次与 `torch.optim.AdamW` 比较，能分别检查权重衰减和状态保存。[PyTorch AdamW](https://docs.pytorch.org/docs/stable/generated/torch.optim.AdamW.html)

## 给 Agent 的每次工具调用关联结果

**对应练习：重放 Agent 工具调用。** 模型提出工具请求，程序执行工具、记录观察结果，再把结果交给模型继续回答。用预先写好的事件序列替代模型，可以直接复现相同的行为。

**术语**

- 调用 ID 用来标识一次工具请求。练习约定，重复 ID 复用该 ID 的首次结果。
- 观察记录包含调用 ID 和工具返回值。每次收到请求都追加一条观察记录，因此记录条数与实际执行次数可以不同。

初始状态包括空的调用结果字典和空的观察列表。给程序依次输入以下四个事件。

| 事件 | 要保存的变化 | 执行次数 |
| --- | --- | --- |
| 调用 `c1: sum([2,5])` | 保存 `c1 → 7`，追加观察 `(c1,7)` | 1 |
| 再次收到 `c1: sum([2,5])` | 读取已保存的 7，再追加观察 `(c1,7)` | 1 |
| 收到最终文本「总和是 7」 | 保存最终文本，结束循环 | 1 |
| 事件列表中还有调用 c2 | 已结束的循环保留上一行结果 | 1 |

**自己设计一次测试。** 把第二个事件的 ID 改为 c2，实际执行次数应增加到 2。再把第一个事件改成未知工具，随后重复原 ID，预期两次观察都含同一个错误结果。讨论真实有副作用的工具时，要进一步说明进程重启期间如何复用同一个调用 ID，以及工具端怎样持久保存执行结果。[Hugging Face Agent 工具循环](https://huggingface.co/learn/agents-course/en/unit1/agent-steps-and-structure)
